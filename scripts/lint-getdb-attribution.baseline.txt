# Task #1724 Phase 4.1 — Baseline of UNATTRIBUTED `getDb()` call sites
# that pre-date the AST-level attribution lint guard.
#
# The lint guard (`scripts/lint-getdb-attribution.ts`) parses every TS/TSX
# file in `server/` and `shared/` and asks, for each `getDb()` call:
# is it lexically inside a callback passed to `withDbAttribution(...)`,
# `withDbHoldLabel(...)`, or `setCurrentDbHoldLabel(...)`? Calls that
# answer "no" are unattributed.
#
# This file lists the allowed number of unattributed call sites per file.
# The lint fails when:
#
#   1. A new file appears with any unattributed `getDb()` call and is
#      not listed here.
#   2. A listed file's unattributed count exceeds its baselined number
#      — i.e. a NEW unattributed call site was added inside an
#      already-grandfathered file. (Wrap the new call in
#      `withDbAttribution(...)`; do not just bump the count.)
#   3. A listed file no longer calls `getDb()` (stale entry — remove).
#
# Format: `<path> <count>` per line. Bumping a count is the explicit
# "I checked, the new call also runs inside an attributed caller scope"
# escape hatch and should be exceptional. Comments (`#`) and blank
# lines are ignored.
#
# Files with `getDb()` calls but zero unattributed call sites do NOT
# appear here: leaving them out is *stricter* (any future unattributed
# regression in those files will fail as a brand-new offender).
