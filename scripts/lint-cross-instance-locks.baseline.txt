# Baseline for scripts/lint-cross-instance-locks.ts (Task #2382, shrunk Task #2398).
#
# These files call setInterval(...) and were grandfathered at the Task #2363
# audit snapshot. The Task #2398 re-audit graduated the genuinely-resolved
# entries OUT of this list:
#   - cross-instance-SAFE schedulers (work_queue SKIP-LOCKED claimers,
#     dedupe-keyed enqueue producers, idempotent UPSERT/DELETE maintenance,
#     purely in-process loops, and DB-cooldown-guarded emits) now carry an
#     inline `// @cross-instance-safe: <reason>` annotation and pass via that.
#   - genuinely-UNSAFE run-once jobs (semrushLocationAutoRetryWorker.ts,
#     ris/risAutoPullScheduler.ts) now take `withWorkerSingletonLock(...)` and
#     pass via lock-helper detection.
#
# What REMAINS here is the residue that is neither cleanly safe nor worth a
# distributed lock: per-process in-memory alert/dedupe schedulers. On a
# multi-instance autoscale deploy each instance keeps its OWN in-memory
# cooldown/dedupe (alertResendGuard, in-process Sets/Maps), so each can emit
# the same alert or aggregate over only its own slice. The blast radius is
# duplicate *alert noise* (or per-instance aggregation skew), not duplicate
# external writes or money — too low-harm to justify a Postgres advisory lock
# and the serialization it imposes, but not honestly "safe" either. Revisit if
# alert-dedup is ever centralized in the DB.
#
# Format: one <path> per line; trailing `# ...` comments are ignored. Prefer a
# `// @cross-instance-safe: <reason>` annotation or `withWorkerSingletonLock`
# over adding new entries here.
