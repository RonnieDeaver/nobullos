## Required free-text checks

1. **Sensitive-data scan.** Spot-check ~20 rows from
   `external_call_audits` and confirm `request_dedupe_key`,
   `response_hash`, `caller_label` contain only hashes / labels — no
   raw tokens, no email addresses, no PII. Record verdict here.
2. **Audit growth projection.** Compute hourly insert rate into
   `external_call_audits` over the 70-minute window and project the
   14-day retention size. Flag if it exceeds ~10 GB.
3. **Admin trends panel.** Visit `/admin/db-attribution/trends` and
   confirm: top holds today, longest holds, labels > 10 s,
   background-on-API-pool, external call volume + cache-hit +
   same-response, noisy endpoints, Front recovery backoff. All eight
   panels should render with rows after the rollup cycle completes.

## How to fill this in (operator)

1. After flipping both switches, set "Activation timestamp" to the
   `updated_at` of whichever flipped second.
2. Wait at least 70 minutes (one full hourly rollup cycle on the
   `pool-audit-rollups` worker, plus a buffer).
3. Re-run the §3 / §4 / §7 queries from `1768-baseline.md` (the
   pool-baseline + audit-counts queries) and paste the new numbers
   above.
4. Decide PASS / FAIL using the verdict line. If FAIL → flip both
   switches back and file follow-up.
